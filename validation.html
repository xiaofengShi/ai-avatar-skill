第一次图像调用因 JPEG 的 invalid_image_file 错误未生成结果。将原照转为 PNG 后，用同一份简报调用成功，未作图像质量重试或候选筛选。实际简报见 generation.prompt.txt，人物源图与成片见 README 对照表。公开源图已移除 EXIF、文本等元数据，并核对 PNG 的 IDAT 图像数据未变化。

用户评价“不错”，并要求将此案例加入 GitHub README，状态为“已生成、助手检查、该用户认可并授权公开”。这是单个真实案例，不能推出身份精确还原、跨人物稳定性或模型优越性。

ChatGPT 网页试验（2026-09-21）

在 Chrome 的 ChatGPT 界面实际生成了一张虚构女性照片，未上传私人照片。随后发送完整的首版单消息 workflow 加“用刚刚生成的照片帮我做张头像”，网页直接生成了一张接近修饰照片的头像，没有先询问具体用途。补充技术大会用途后再次得到图像；画风仍偏摄影，未返回要求的独立下载链接。这不是“用途澄清通过”，也不是稳定匹配参考画风的证据。

本次网页操作经历了粘贴无效果、多行模拟键盘输入被拆分、元素 ID 失效等自动化问题；实际发送的首版完整 prompt 经文本框接口输入，界面对 Markdown 添加了转义符。试验还有已生成源图的上下文，不能当作干净的新对话盲测。没有通过分享按钮发布对话或图片。

据此，ChatGPT 入口改为两条消息：先只做方案沟通，再明确“按方案生成”。共享 workflow 也明确了“头像”不等于实际用途。修订版在网页实际完成了方案与生成两步：方案明确引用最初源图，围绕大会用途决定酒红服装、灰蓝背景、自然神态和绘画语言；在收到第二条消息后生成了图片。随后在一个新对话中发送修订版方案阶段加“我想把一张照片做成好看的头像”，实际只收到“这张图主要用在哪里？”，没有生成图像。

状态：两阶段基本交互已验证；风格一致性未证明。最终网页图像在可见尺寸下仍偏写实，绘画感主要体现在背景与衣服，不能称为精确匹配 Codex 参考风格。ChatGPT 没有返回可核验的实际图像工具 prompt、模型版本、seed 或下载文件；网页输出未收入仓库。本文图像示例均来自 Codex 生成记录。ChatGPT 测试使用同一对话中生成的虚构源图，没有测试真实用户上传照片的路径；新对话澄清测试同时缺少用途和照片。

圆形裁切与小尺寸

两组 Codex 成片已在 Chrome 页面实际查看 40、64、128、256 CSS 像素、浅色与深色背景的圆形裁切。发型与脸部没有被圆边误切，眼镜与面部轮廓在小图仍可辨认。40 px 下胡茬、细密卷发等纹理不可细辨，这是缩略图的显示限制。没有将这次助手视觉检查写成真人用户认可。

预览开发时曾尝试把大体积图片放进 CSS 自定义属性，实际浏览器中出现空白；已改回普通图像元素并复看通过。仓库样例使用相对引用模式，标准用法仍生成独立内嵌 HTML。
